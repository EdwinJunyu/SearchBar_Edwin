## 内容和资源

独立路径按从 1 开始的物理序号读取原书，核对原词头和正文，再从生成的两个 MDX 读回各来源清单和实际展示内容。资源逐路径核对二进制数据。新世纪 MDD 有 1,040 项，另加入外置 CSS 和封面，合计 1,042 项、16,180,237 个原始资源字节。

源目录存在以下异常。成品保存原文和对应引用，不能从现有文件还原缺失的图像或排版。

- 牛津原书 124 条记录引用了缺失的 50 个图片文件，共 184 次。这些图片包含部分音标字符。
- 现代汉英的 376,636 条正文都引用了缺失的 `sf_cb.css`。
- 新世纪原书部分内嵌图片的属性中混入 HTML。外置的 2,334 处图片引用所用的 1,019 个不同键均在原 MDD 中找到。
- 英辞郎有 12 条、三省堂有 1 条原始空正文，均保留来源和序号。新世纪 9,560 条正文中的 9,851 个 `javascript:;` 引用均没有脚本动作。用原版 GoldenDict 和合并页实点 `accelerator` 时，页面都停留在原词条。英辞郎两处 `URL(www.abc.dot.com)` 是原释义里的文字。

## 阅读器和构建

生成器使用固定版本 mdict-utils 1.3.14 的 MDX/MDD V2 写入器，原档读取支持这批输入实际使用的 LZO、zlib 与索引编码。MDX 使用 UTF-8。公开词头保留原码点。来源内部的跳转另按原 GoldenDict 版本的查找规则求有序落点。每条展示记录携带原来源、序号、词头和正文，供 E_Search 复用原书解析器，也供独立审计逐条比对。来源辅助页用于跨词头跳转。

E_Search 独立库仍可按来源检索，设置中的双卷入口同时校验两个 MDX 和配套 MDD。可从合并页浏览来源标签、义项、图片与同源链接，使用返回按钮回到上一页。旧的个人数据库与这份独立库分开。

## 原书跳转和阅读器差异

逐条对照了 1,059,336 个引用，覆盖现代汉英 231,792 个、牛津 40,037 个、三省堂 538,317 个和新世纪 249,190 个。独立读取本机原版 GoldenDict 为原书生成的二进制索引，按来源和物理序号比对目标序列。在旧版候选中发现的 507 处漏选已按原版规则修正。现代汉英 1,183 个子项在第二或第三条同形记录中才出现，184 个子项在多个同形记录中都存在。合并页保留全部候选并选取首个真实锚点。以现代汉英 #234820 为例，在 GoldenDict 点「朱墨」，打开的页面包含 #180022、#180023，子项链接明确指向后者的 `subEntry1`。

GoldenDict 与 E_Search 对一条新世纪原生跳转的实体解码不同。成品给这条注明「E_Search 补充跳转」，保留两种读法。对 GoldenDict 原书本身无同源命中的引用，合并页使用本来源的缺失目标键；其他词书的无关同名记录不会代接。GoldenDict 的联想和历史可显示生成的辅助键。E_Search 的普通候选由原书检索项产生。

三省堂 #520436 的词头以全角减号开头，即「－in」，例词有 *sit-in*、*teach-in* 和 *phone-in*。固定版 GoldenDict 的一个索引桶在合并前有 64 项，合并后达到 1,029 项。它会跳过第 1,024 项之后的某些匹配。对照词典实测证明，在公开词头之外增加一个以制表符起首的辅助键，能让读者照常输入「－in」并读到原文。辅助页的显示内容取自同一公开页。

本机 GoldenDict 1.5.0-RC2-254-gbd95948（Qt 4.8.6）对这两卷的 2,795,892 个公开词头逐一比对。原书可直接查到其中的 2,795,877 个，成品可直接查到 2,795,880 个。原先可达的词头全部保留，三省堂的「－じょう」「－せい」「－とう」增加了直接入口。另有 12 个词头在这个版本里原本就无法直接输入查到，包括 10 个超长词头及「－い」「－し」。这些记录仍在成品内。195,172 个辅助页全部可达。在每个来源自己的原书索引中，1,059,336 处引用有 550,762 处直接命中、508,574 处没有直接命中；合并后的目标及顺序与基准对照无差异。

最终两卷同载时，在原生 GoldenDict 窗口从三省堂 DC 点 AC，依次显示 #291、#292、#294、#296、#83274；从现代汉英 #234820 点「朱墨」，由阅读器记录的真实目标片段指向 #180023；新世纪 #24447 的图像也在词条内显示。截图与原版对照见交付目录的 `verification/GoldenDict`。实际 WPF/WebView2 程序另核验了 14 页、66 个来源段，包括英辞郎所在日语卷、新世纪 MDD 图标和原生补充跳转。实机图像、点击与全页结构检查的覆盖范围分别记在 `verification/词书合并-WebView2实测.md`。

## E_Search 索引与耗时

发布程序构建号为 `0.2.0+worktree-82397e1905ff36b5`。完整导入在一次事务中写入双卷，实测 478.85 秒，进程工作集峰值 478,572,544 字节，数据库逻辑大小 6,821,175,296 字节。再次用交付程序从空库导入，在每卷起止事件之间约每 80 毫秒采样一次。中英卷期间进程工作集峰值为 148,484,096 字节，日语卷期间为 488,091,648 字节，两阶段共享同一个进程和事务。完整采样记录见 `verification/d11-import-by-volume.json`。不同机器、缓存状态和磁盘会影响耗时。

| 卷 | 查词样本 | 首次中位数 / P95 | 立即重复中位数 / P95 | 最长公开页 HTML |
|---|---:|---:|---:|---|
| 中英 | 230 | 1.22 / 3.15 ms | 0.57 / 1.87 ms | 「自动」，203,364 字节 |
| 日语 | 701 | 1.21 / 5.09 ms | 0.62 / 2.00 ms | 英辞郎 `look`，原词头末尾含两个空格，4,628,754 字节 |

上述 931 个样本使用相同数据库连接，保留操作系统文件缓存，按来源、顺序和正文与原词库核对，差异为零。35 项项目回归及随包程序的 11 个实际查词核验均通过。对真实 E_Search 索引逐行核对时，3,271,081 条词条的全部字段及 4,797,508 条检索项均与独立导入八部原书的结果一致，SQLite 的外键检查为零错误。交付目录内的数据库副本也已通过完整表计数、SQLite 快速完整性检查、资源哈希及随包程序查词。在桌面账户下再次打开成品，11 项查词通过。启动脚本已分别用 1、2、3 验证中英、日语及双卷入口。

## 逐条证据

两份独立审计报告分别为 `verification/词书合并-A5-独立审计.json` 和 `verification/词书合并-B5-独立审计.json`。逐条校验的原词头、来源序号和正文均一致，1,042 份资源与原书按路径和字节核对一致。两轮审计除读取的工作目录之外，各个结果字段相同。

交付目录 `verification/逐条溯源.zip` 按原书保存 3,271,081 条来源映射。每行包含原序号、原词头、严格解码正文的 SHA-256、目标卷、目标词头、段落与代表来源。包内另有 1,059,336 处引用、1,786,232 处可逆改写、231,792 个片段和资源映射。JSONL 各文件首行列出字段名，完整原文可从两卷的来源清单复核。ZIP 已通过逐文件 CRC 检查。

## 复建

在项目根目录运行，`--source-root` 指向原八本所在的辞书目录；具体文件名见 `merge_dictionaries.py`。A、B 分别使用新目录，以保留中断记录。按固定版本安装项目所用 .NET SDK、PowerShell、Python 和 LZO 库，并准备 `mdict_io.py`、`merge_render.py` 中列出的已校验离线依赖。

```powershell
python -B -X utf8 mdict_io.py --self-test
python -B -X utf8 merge_dictionaries.py self-test
python -B -X utf8 -m unittest test_merge_render.py
python -B -X utf8 merge_dictionaries.py stage --source-root "<原书目录>" --stage ".data/rebuild-A/stage"
python -B -X utf8 merge_dictionaries.py build --stage ".data/rebuild-A/stage" --output ".data/rebuild-A/book"
python -B -X utf8 merge_dictionaries.py stage --source-root "<原书目录>" --stage ".data/rebuild-B/stage"
python -B -X utf8 merge_dictionaries.py build --stage ".data/rebuild-B/stage" --output ".data/rebuild-B/book"
python -B -X utf8 merge_dictionaries.py compare ".data/rebuild-A/book" ".data/rebuild-B/book"
```

最终阅读器与文件核验使用 `audit_merged.py`。可在原项目中运行，也可以进入交付文件夹的「复建工具」，使用随书的 `app/E_Search.exe` 建立原书链接基准。完整复建需要原来的八个 MDX 及新世纪的配套资源。以下控制报告来自加入「－in」兼容入口以前的 GoldenDict 真实索引对照。

```powershell
python -B -X utf8 audit_merged.py --self-test
python -B -X utf8 audit_merged.py --stage ".data/rebuild-A/stage" --books ".data/rebuild-A/book" --lookup-profile goldendict --check-dom --control-index-report "reports/词书合并-A4-GoldenDict实际索引.json" --output ".data/rebuild-A/independent-audit.json"
```
